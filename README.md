# Учет финансов

Консольное приложение для ведения личного финансового учёта. Приложение позволяет управлять банковскими счетами, категориями операций и самими операциями (доходами/расходами), а также проводить аналитические расчёты, импортировать и экспортировать данные в различные форматы.


## Функциональность

- **Управление доменной моделью:**
    - **BankAccount:** создание, редактирование и удаление банковских счетов (атрибуты: id, name, balance).
    - **Category:** управление категориями операций (атрибуты: id, type, name). Поддерживаются типы «доход» и «расход».
    - **Operation:** операции, связывающие счета и категории. Хранят информацию о сумме, дате и описании.

- **Аналитика:**
    - Подсчёт разницы между доходами и расходами за заданный период.
    - Группировка операций по категориям с выводом суммарных значений.
    - Возможность расширения аналитических сценариев.

- **Импорт и экспорт данных:**
    - Поддержка форматов JSON, YAML и Excel.
    - Импорт данных из файлов с последующим обновлением in-memory хранилищ.
    - Экспорт текущих данных в выбранный формат.

- **Консольное меню:**
    - Интерактивный пользовательский интерфейс, позволяющий выбирать действия по управлению счетами, категориями, операциями, аналитикой, импортом и экспортом.

## Установка и запуск

### Сборка проекта

1. **Клонируйте репозиторий (если необходимо):**
   ```
   git clone https://github.com/zxchelik/KPOBHW1.git
   cd KPOBHW1/App
   ```

2. **Сборка проекта:**
   В командной строке выполните команду:
   ```
   dotnet build
   ```
   Это соберёт решение и все проекты внутри него.

### Запуск приложения

1. Перейдите в папку с проектом App (например, `App`):
   ```
   cd App
   ```

2. Запустите приложение:
   ```
   dotnet run
   ```
   После запуска в консоли отобразится главное меню, где вы сможете выбрать необходимые действия.

## Использование

### Основное меню

При запуске приложения в консоли отобразится меню с опциями:
- **1. Управление счетами:** Просмотр, добавление, редактирование и удаление банковских счетов.
- **2. Управление категориями:** Просмотр, добавление, редактирование и удаление категорий.
- **3. Управление операциями:** Просмотр, добавление, редактирование и удаление операций (доходов/расходов).
- **4. Аналитика:** Вычисление разницы между доходами и расходами за выбранный период, группировка операций по категориям.
- **5. Импорт данных:** Загрузка данных из файла (JSON, YAML, Excel) и обновление хранилищ.
- **6. Экспорт данных:** Сохранение текущих данных в файл выбранного формата.
- **7. Выход:** Завершение работы приложения.

### Примеры работы

- **Добавление нового счета:** При выборе опции «Добавить счет» введите название счета и начальный баланс.
- **Добавление операции:** При выборе опции «Добавить операцию» введите ID существующего счета и категории, сумму операции, дату (формат: yyyy-MM-dd) и описание (необязательно). При создании операции автоматически обновляется баланс выбранного счета.
- **Аналитика:** В разделе «Аналитика» можно задать период (начальную и конечную даты) для подсчёта разницы между доходами и расходами, а также просмотреть суммарные значения операций по категориям.

## Архитектура и паттерны

Проект разработан с использованием принципов SOLID, GRASP и ряда паттернов проектирования GoF:

### Применённые паттерны

- **Фабрика (Factory Pattern)**
    - *EntityFactory:* Создаёт экземпляры банковских счетов, категорий и операций с необходимой валидацией входных данных.
    - *FinanceContextFactory:* Объединяет данные из разных хранилищ в единый объект контекста, что упрощает работу с финансовыми данными.

- **Фасад (Facade Pattern)**
    - *ImportFacade и ExportFacade:* Скрывают сложность выбора конкретного алгоритма импорта/экспорта в зависимости от формата файла. Клиентский код обращается к фасаду, который сам определяет, какой класс использовать.

- **Команда (Command Pattern)**
    - Команды (ImportDataCommand, ExportDataCommand, GetGroupedByCategoryCommand, GetBalanceDifferenceCommand) инкапсулируют отдельные операции как объекты. Это позволяет отделить вызов команды от её выполнения и легко добавлять новые сценарии.

- **Стратегия (Strategy Pattern)**
    - Интерфейсы IDataImporter и IDataExporter и их реализации (JsonImporter, ExcelImporter, YamlImporter) позволяют динамически выбирать алгоритм импорта/экспорта в зависимости от переданного формата файла.

- **Шаблонный метод (Template Method Pattern)**
    - В классе ExcelImporter методы чтения данных (ReadBankAccounts, ReadCategories, ReadOperations) объявлены как protected virtual, что позволяет создавать подклассы с переопределением отдельных этапов алгоритма.

- **DTO (Data Transfer Object Pattern)**
    - *FinanceContextDto* используется для передачи данных между слоями приложения при сериализации и десериализации, отделяя формат передачи от внутренней модели.
    - P.S. Реализация слабая. Нужен был какой-то такой объект, и решил подвезать :)    

- **Репозиторий / Хранилище (Repository Pattern)**
    - Интерфейс IStore<T> и его реализации (MemoryBankAccountStore, MemoryCategoryStore, MemoryOperationStore) абстрагируют доступ к данным, что упрощает замену in-memory хранилища на базу данных без изменения бизнес-логики.

- **Инверсия зависимостей (Dependency Inversion Principle)**
    - Код зависит от абстракций (интерфейсов IAnalyticsService, IDataImporter, IStore<T>), что повышает модульность и тестируемость, позволяя подменять конкретные реализации на моки или стабы в тестовой среде.

## Тестирование

- Проект **Core** покрыт модульными тестами более чем на 80% (за исключением части, связанной с файловыми операциями, по причине сложности тестирования файловых систем).
- Основные сценарии, такие как импорт/экспорт данных, аналитика и работа с хранилищами, протестированы с использованием фреймворка xUnit.
- Для тестирования используется Dependency Injection, что позволяет легко подменять зависимости и обеспечивать изоляцию модулей.
